# Playground parity with Plexus — observed and implemented

## Comparison

Authenticated admin desktop (~1256px) and narrow (390×844px) snapshots were taken on September 30/October 1, 2026 at Plexus `http://100.121.114.16:4000/ui/playground` and Trefoil `http://127.0.0.1:8080/playground`. Screenshots: `/tmp/plexus-playground-reference.png`, `/tmp/trefoil-playground-parity.png`, `/tmp/plexus-playground-mobile.png`, `/tmp/trefoil-playground-mobile-matched.png`. Plexus shows a full-width **Test Configuration** card (Key, Model, API, Tool Mode and key-policy summary), a large **Chat Simulation** card, and **Routing Decision** card. Before this change, Trefoil put a small Conversation card next to a Request settings sidebar and showed no routing card (`frontend/src/pages/Playground.tsx` prior diff); that layout was visibly unlike Plexus. The live Plexus revision is not established by the reference checkout. Trefoil intentionally keeps its own name, mark, light palette and orange primary color (`frontend/src/components/layout/AppShell.tsx`, `frontend/src/globals.css:29-90`).

## Contract

Plexus reference `.reference/plexus/packages/frontend/src/pages/Playground.tsx:137-220,316-535` selects a client key and model, offers API options chat/messages/responses/gemini, sample tools, policy summary, streaming chat simulation and routing decision. Trefoil currently has a working OpenAI-compatible chat completions Playground only; other API modes and sample tools remain disabled and labeled unavailable, rather than pretending to work. Existing signed-in admin can select a configured key or use the session; override key is hidden in Advanced request settings and not persisted. Model aliases and direct provider/model choices come from the authenticated catalog and (admin-only) provider/alias configuration (`frontend/src/pages/Playground.tsx:15-75`). A selected key's allow/exclude model and provider lists are displayed, but server auth still decides access (`backend/src/inference.rs:1829-1851,3291-3307`). Advanced optional temperature is omitted when blank; max tokens defaults to 128 and both are validated before constructing POST `/v1/chat/completions` (`frontend/src/pages/Playground.tsx:76-115`). A success only appears when the response contains assistant text; rejected or empty responses show an alert and raw JSON (`frontend/src/pages/Playground.tsx:87-110`).

## Layout and settings changes

`frontend/src/pages/Playground.tsx:117-159` implements Plexus's vertical page hierarchy: page header/Refresh, Test Configuration with a 1:2 desktop selector/policy split, Chat Simulation with a tall scrollable transcript and bottom composer, and a Routing Decision panel. At 390px the config columns stack and the composer remains visible. The configuration's Key/Model/API/Tool Mode controls follow the reference's positions; only chat is enabled, and tool mode is disabled until implemented. Optional key override, direct provider/model, temperature and max tokens live inside a disclosure to keep the primary card concise. Trefoil branding and CSS variables are unchanged. Routing Decision displays Trefoil provider and response model when available, with a disclaimer that it does **not** claim to know the final Plexus provider; this is less detailed than Plexus's retry trail but avoids fabricated metadata.

Desktop admin selected `luna-via-plexus`, opened Advanced settings, set max tokens 16, left temperature blank, submitted a non-sensitive one-word request; captured POST body had `model: luna-via-plexus`, `max_tokens: 16` and no `temperature`. HTTP 200 yielded an Assistant reply and `Routed` status. The 390px flow found Test Configuration, Chat Simulation and Routing Decision, enabled model and composer, and no horizontal overflow. Bad direct route syntax displayed an alert before send; unknown provider/model returned HTTP 404 and no false assistant reply. `npm run build --prefix frontend`, `git diff --check`, and `/healthz` 200 passed. Persistent agent-browser session `trefoil-desktop` on CDP 19330 also observed live assistant text and HTTP 200 with no page errors.

## Remaining

Not 1:1 functionally: Trefoil does not yet implement Plexus's messages/responses/gemini chat modes, sample browser tool calls, streaming simulation, file attachments, detailed retry/attempt trail, policy-aware model disabling, or custom IP/quotas preflight. These are explicit unsupported states. No-model and provider-unavailable conditions are shown by source error paths but were not reproduced against a live empty catalog or down provider. The screenshot matching is structural at desktop/mobile while Trefoil's palette and brand intentionally differ; visual differences in exact spacing/type sizes remain. No unit tests were added.
