# Trefoil → Plexus Luna testing upstream

## Contract

Trefoil independently dispatches `POST /v1/chat/completions` to a configured provider's `api_base_url + /chat/completions` with Bearer authentication, selecting the provider/model via `target_groups` (`backend/src/inference.rs:1904-1989`, `backend/src/aliases.rs:145-172`). The Trefoil frontend proxies `/v1/` to this backend (`frontend/nginx.conf:17-23`). Plexus at `http://100.121.114.16:4000/v1` advertises alias `luna` (verified through `/v1/models`); its admin alias resolves to `gpt-6-luna` through `codex-oauth` and `codex-oauth-2`. A fresh, dedicated Plexus inference key restricted to alias `luna` is preferable to copying an existing broad shared key. User authorized connecting Plexus Luna as a test upstream; do not change Plexus providers or existing Trefoil `luna` alias. Use Trefoil provider `plexus-luna` and a **different** alias `luna-via-plexus`: `inference_targets` prioritizes a provider-slug match over alias expansion (`backend/src/inference.rs:3291-3307`).

## Configuration

A dedicated Plexus inference key named `trefoil-luna-upstream` was created through `PUT /v0/management/keys/:name` with `allowedModels: [luna]` and providers limited to the two verified Luna backing providers. It was re-read with those restrictions and an active status; its value was transferred directly in process memory into Trefoil's new `plexus-luna` provider at `http://100.121.114.16:4000/v1`. An initial Trefoil alias also named `plexus-luna` was created, but a chat request discovered the direct-provider naming collision; that alias was replaced with **`luna-via-plexus`**, mapped in order to `{provider: plexus-luna, model: luna}`. The old conflicting alias was deleted. No tracked credential file was changed; neither this document nor tool output includes the key. Before/after counts: Trefoil providers 6→7, aliases 33→34, Plexus keys 14→15; the pre-existing Trefoil `luna` alias remains unchanged. These resources are persisted via Trefoil/Plexus management APIs (`backend/src/providers.rs:652-685`, `backend/src/aliases.rs:464-509`). This is HTTP over the Tailscale address and is limited to the trusted network, not suitable for untrusted links.

## Verification

The admin-only Trefoil `/v0/management/test` probe to provider `plexus-luna`, upstream model `luna`, API type `chat` returned HTTP 200 with `success: true` in 1773 ms. A separate non-streaming `POST http://127.0.0.1:8080/v1/chat/completions` using Trefoil's admin key via `x-api-key`, model **`luna-via-plexus`**, a non-sensitive one-word prompt and 16-token cap returned **HTTP 200**, one choice, and response model `gpt-6-luna`. Trefoil's completed usage row at approximately `2026-10-01 01:11:59 UTC` recorded provider `plexus-luna`, incoming alias `luna-via-plexus`, `success`, output tokens 5; the temporally correlated Plexus usage row under the dedicated key recorded incoming alias `luna`, final provider `codex-oauth-2`, final model `gpt-6-luna`, `success`, output tokens 5. Timestamp offset was ~136 ms; request IDs differ across gateways, so this is strong timestamp/key/token correlation, not a shared-ID proof. The negative unknown model returned 404 `model_not_found`; invalid Trefoil Bearer key returned 401 `auth_error`. No key or prompt content is recorded here. `git diff --check` passed; a bounded credential-like pattern scan found none in this document.

## Blockers

No current access blocker. The initial alias/provider name collision was resolved without changing the existing `luna` alias. The backend and frontend remain healthy. The test exercised chat completion only; streaming, other API types, quota/cost accounting, failover and restart persistence were not tested.
