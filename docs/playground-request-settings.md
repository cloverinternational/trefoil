# Playground request settings — observed contract and fix

## Contract

The protected `/playground` route is registered in `frontend/src/App.tsx:28-48`. A logged-in principal is held by `frontend/src/contexts/AuthContext.tsx:22-73`; the browser may use the signed-in credential through the `x-api-key` header. The backend authenticates inference and returns alias IDs at `/v1/models` (`backend/src/inference.rs:1829-1867`) and sends chat to a provider with Bearer auth after target expansion (`backend/src/inference.rs:1904-1989`). An alias is usable only if a target group resolves to a configured, enabled provider, and a provider slug can shadow an alias of the same name (`backend/src/inference.rs:3235-3307`).

`frontend/src/pages/Playground.tsx` holds selected model/alias, optional credential override, prompt, optional temperature, max tokens, response and error. It reads the model catalog and, for admin sessions, filters out aliases lacking a usable target and offers direct provider/model routes derived from configured targets. Submitting POST `/v1/chat/completions` sends the exact selected alias (or explicit provider/model), trimmed prompt and validated generation settings; successful responses require actual assistant text, and rejected/empty responses show an explicit error with raw JSON available. Credentials are not persisted by the Playground.

## Blockers found

- Before the change, the settings panel always required a second inference key even though an admin session was active; a headful browser visit to `http://127.0.0.1:8080/playground` showed a disabled model selector and `/v1/models` returned HTTP 401. The backend permits an admin credential in `x-api-key` (`backend/src/inference.rs:1841-1851`), so the UI could use the authenticated session rather than block discovery.
- `/v1/models` advertises aliases without checking target groups, including the existing Trefoil `luna` with no target. Selecting one led to a route error, not a model failure. An alias slug equal to a provider slug is instead routed directly to the provider (`backend/src/inference.rs:3291-3307`). Admin model choices now exclude unrouteable aliases and name-colliding aliases; a direct provider/model field permits testing an upstream target independently of alias configuration.
- A forced `temperature: 0.7` was sent with every request; it is now omitted by default so upstream-specific defaults remain in control. A blank or out-of-range max-token/temperature value is rejected before sending. A successful HTTP response with no assistant text is no longer presented as a valid reply.

## Changes

`frontend/src/pages/Playground.tsx:13-112` now uses the signed-in session unless an explicit key override is entered; does not write the override to localStorage; builds discoverable admin alias/provider choices using existing management adapters; validates direct `provider/model`, temperature and max-token inputs; omits temperature when blank; preserves the selected credential's permissions on the server; and exposes backend response errors rather than claiming success. No provider, alias, key or backend configuration was changed for this fix. `frontend/e2e/playground-live.spec.ts:1-48` covers the user-visible flows only; no unit-test file was added.
