# Usage Analytics, Performance, and custom dashboards — implementation plan

## Scope and decisions

The user requested a one-shot implementation of the observed Plexus Usage Analytics and Performance experiences, extended with modular Grafana/Metabase-style dashboards. Trefoil remains independently hosted, with its own palette/brand and **ECharts**. The user selected: **server-stored** dashboards; one explicit group label per API key; snapshot the group onto each request when recorded (preexisting records remain Ungrouped); admin-editable shared layouts that limited-key viewers can open only with server-scoped results; a **semantic query builder** with arbitrary combinations of approved dimensions, filters, aggregations and safe formulas rather than raw SQL; and labeled E2E telemetry inserted into the existing local Trefoil DB then removed. No unit tests; browser E2E only, backed by the real Trefoil service and PostgreSQL. Production Plexus is read-only.

## Integration and data contract

- Frontend routes: `frontend/src/App.tsx:38-65` routes `/usage` to `DetailedUsage` and `/metrics` to Prometheus-oriented `Metrics`, while the dashboard links point there (`frontend/src/pages/Dashboard.tsx:228-258`). Keep legacy URLs, add dashboard sections and a custom dashboard route. Existing `frontend/src/lib/api.ts:122-173` has summary/list types but omits recorded TTFT/TPS in usage records. `frontend/src/pages/DetailedUsage.tsx` and `Metrics.tsx` already use ECharts.
- Server: `backend/src/lib.rs:55-93` merges routers; `backend/src/usage.rs:184-230,265-344` lists and summarizes usage and scopes limited principals to their key. `backend/src/performance.rs:15-70` is admin-only with per-provider/target-model aggregates. `request_usage` holds `api_key`, model, start/duration/TTFT/TPS (`backend/migrations/0000_round_millenium_guard.sql:1-29`); `KeyConfig` lacks a group (`backend/src/state.rs:16-42`). `backend/src/auth.rs:31-35` distinguishes admin and limited key principals. Inspect key mutation, state persistence and every usage insert path before changing them; no client-supplied group attribution.
- Metric definitions: throughput TPS = recorded `tokens_per_sec` (streaming output tokens divided by generation duration after TTFT); TTFT = recorded `ttft_ms` in milliseconds. Aggregate as sample-weighted mean over **non-null observations** per bucket/dimension, not a mean of means; show `—` and sample count zero when none. Request-rate and output-token-rate are separate measures, not called TPS. UTC-aligned bucket boundaries with explicit range and bucket width; a request belongs to its recorded start bucket. Group filter is equality against the request-time group snapshot; preexisting requests and keys without a group are `Ungrouped`. Never backfill old usage from the current key assignment. Ensure provider performance rows with `sample_count=0` show unknown, not 0 TTFT.
- Authorization: admin can choose all model/group/key dimensions; limited principal can only see its own request rows even when a shared dashboard has broader filters or a forged direct API request. Server must apply principal scope *before* grouping, filtering, and aggregation. Shared definitions contain no credentials and do not grant access. Explicit forbidden/validation errors for denied operations and malformed query configs; bounded time windows, panel count, result size, dimensions and formula AST depth. DB errors return explicit server failures, not fabricated empty series.

## Expected acceptance and limitations

Both routes must show real Trefoil telemetry and matching observed Plexus sections, with additional group and custom-builder controls. Admin creates a named layout, adds/reorders/query-edits panels, saves, reloads, and sees the same config; limited user can view it but sees only its own data. A second key's metric never leaks through a URL filter, saved config, or direct API. Missing TTFT/TPS remains unknown, not zero. E2E checks compare displayed values with known DB fixtures and confirm cleanup. Full Plexus UI pixel identity is not the goal because the user explicitly retained Trefoil colors/brand and specified ECharts. Arbitrary raw SQL, external Grafana/Metabase embedding, and production Plexus mutations are out of scope.

## Telemetry capture

October 1, 2026: a real-request audit found the **first loss before storage**. `backend/src/inference.rs` recorded tokens and duration from nonstream JSON and streaming SSE, but `backend/src/database.rs#update_request_usage_metrics` wrote neither TTFT nor TPS. `/v0/management/usage/summary` and `/v0/management/analytics/query` could aggregate these existing nullable columns but had no newly captured samples; `/v0/management/performance` read `provider_performance`, to which no Rust request path inserted samples. The live baseline was 11 usage rows, 10 with output tokens, **0 TTFT and 0 TPS**, and 0 performance samples. The older read-only frontend memory about missing display fields was true for the request lists, but the newer AnalyticsDashboard already has TPS/TTFT panels; this was primarily a capture gap.

`backend/src/inference.rs#StreamAccounting` now marks TTFT (milliseconds since request start) only on the first **nonempty content delta** observed in a completed SSE stream—not on response headers, role-only events or usage-only events. On successful completion, generation TPS = reported positive output tokens × 1000 / positive elapsed milliseconds *after* first output; without both measurements generation TPS stays NULL. A successful nonstream response with positive reported output tokens and positive request duration records **E2E TPS** = output tokens × 1000 / full duration (milliseconds); TTFT and generation TPS remain NULL. A successful stream without a recognized first content delta can have E2E TPS only if output count and elapsed time are known. Failure/cancellation does not create a performance sample and does not claim a successful measured TPS/TTFT. The stream finalizer remains one-shot. Duration and token fields retain their prior accounting paths; no fabricated zero is stored for missing timing. `backend/src/database.rs#update_request_usage_metrics` now persists nullable `ttft_ms`, `tokens_per_sec`, `e2e_tokens_per_sec`; `#record_provider_performance` inserts successful measured samples. `backend/migrations/0091_request_e2e_throughput.sql` adds the missing request usage E2E TPS column (migration 91 applied locally); `backend/src/usage.rs#list_usage` returns nullable `ttftMs`, `tokensPerSec`, `e2eTokensPerSec` under the unchanged principal scope. Server-side analytics averages only non-null measurements.

### Reconnection boundary verification

Inference SSE is **not resumable in place**: `backend/src/inference.rs#accounted_sse_body` finalizes a broken upstream body, while the retry/failover machinery applies before a streamed response is handed to the client. Automatic resume remains unsupported and is not claimed. A truly long-running multi-minute interruption was not exercised.

### Missing terminal marker

A clean HTTP EOF without an SSE `[DONE]` or protocol completion marker previously fell through the stream-drop guard and could be reported as `cancelled` even though the client fully read an incomplete upstream body. `backend/src/inference.rs#accounted_sse_body` now appends one EOF finalizer: if no terminal event finalized the request, it records `error` rather than treating it as a successful completion or a client cancellation. This preserves genuine client-drop cancellation and explicit terminal success/error. A live local upstream sent partial text plus usage counters then cleanly ended without a marker; the E2E usage row retained the observed six output tokens but had `error`, NULL TTFT/TPS/E2E and no provider-performance sample. Combined telemetry E2E passed **6/6**, `cargo check`, frontend build and `git diff --check` passed, fixture counts returned zero. Non-SSE binary speech continues to use its independent EOF-success semantics. No automatic SSE resume is implemented.

### Streaming E2E throughput correction

Plexus's performance storage computes generation throughput over duration *after* first token and **E2E throughput over the full duration**, when a completed request reports positive output tokens. Trefoil was leaving E2E TPS NULL whenever a streamed request had a measured TTFT, incorrectly making the two throughput measures mutually exclusive. `backend/src/inference.rs#StreamAccounting::finalize` now computes E2E TPS for every successfully completed stream with positive output tokens and elapsed time while leaving generation TPS and TTFT rules unchanged. Real delayed Chat and Responses SSE E2E confirms both TPS values are positive, with generation TPS greater than E2E TPS; failed, cancelled and markerless EOF still have NULL metrics. Combined telemetry browser suite passed **6/6**, `cargo check` and `git diff --check` passed; fixtures cleaned. No E2E claim is made for cost accounting or all other API families.
