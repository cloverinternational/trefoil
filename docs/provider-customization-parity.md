## Contract

`frontend/src/pages/Providers.tsx` owns list, form, OAuth session and modal. `frontend/src/lib/api.ts` calls `/v0/management/providers/:slug`, `/v0/management/oauth/providers`, `/v0/management/oauth/sessions`. The typed URL/map changes in the later section supersede the initial scalar-only limitation. Existing OAuth authorization/callback and secret handling remain backend-owned; no credential values belong in documentation.

Quota checker selection now loads the admin registry from `/v0/management/quota-checker-types` and offers supported type labels instead of arbitrary free text. A broad post-test audit found **one older `quota-e2e-*` provider** left from a prior failing test iteration; it has no matching request-usage rows, but its ownership is not independently established, so it was not deleted by prefix. To reduce silent quota overwrites between opening Edit and saving, the form now keeps a snapshot of the checker's config. An initial test immediately re-opened from stale list state and failed; it now explicitly refreshes after the conflict. Provider suite passed **5/5**. Two older `quota-e2e-*` fixture providers remain from failed iterations; their ownership is ambiguous and they were not deleted by prefix. The current test asserts cleanup of its own ID.

An attempted quota-only server CAS was **not shipped**: it could atomically compare/update the quota columns, but the existing provider Edit saves URL/models/name/other flags through a separate full-record PATCH. Combining those two requests would let the first save partially succeed before a quota conflict, defeating the user's expectation that the whole form save either succeeds or fails. The prototype route/helper/client adapter were removed before deployment; `cargo check`, frontend build, `git diff --check` and provider browser suite **5/5** passed afterward. True atomicity requires one versioned conditional *full-provider* update in the database, coordinating management PUT/PATCH and backup writes before claiming race-free behavior. The current client-side checker comparison remains a best-effort warning, not a guarantee.

That full-provider conditional edit is now implemented for **versioned** PATCH requests. Migration `backend/migrations/0092_provider_version.sql` gives existing provider records a revision; `backend/src/database.rs#update_provider_if_version` updates all persisted provider fields and increments that revision in one SQL statement only when `slug` and `expectedVersion` still match. `backend/src/providers.rs#patch_provider` returns 409 on stale revision without changing routing, credentials or quota. The Trefoil editor sends the revision from its opened snapshot; it still warns early on checker changes and now receives a server-enforced final conflict if another edit lands after its re-read. Two real local E2E cases verified a stale direct full-record patch gets 409 with neither display name nor quota partially changed, and a stale browser editor gets an alert while a newer route remains intact. After refreshing, normal preset/quota edits passed; provider suite **7/7**, migration 92 applied, `cargo check`, frontend build and diff check passed. Unversioned integrations and cross-process state refresh are not yet guaranteed race-free, and the previous two ambiguous `quota-e2e-*` rows were not broadly deleted.

An isolated local Compose restart check (`frontend/e2e/provider-version-restart-live.spec.ts`) created a disposable provider, incremented its revision through a conditional edit, restarted only the backend, then re-read the same revision and display name. The pre-restart revision still received HTTP 409 and did not overwrite the saved value. E2E passed **1/1**; backend returned healthy, the tagged provider was removed and no provider had a revision below 1. The provider-management path now re-reads persisted providers for list/get and reads the current persisted provider before merging PATCH instead of trusting only the process-local startup snapshot. A local provider browser regression passed **7/7** with this change. The read uses the existing JSONB/text decoder; database read errors return explicit server errors rather than stale cached success. **This is not full cross-process synchronization**: inference routing, quota polling and other routes still read process-local `state.inner.providers`, which is not updated when a different backend instance writes to PostgreSQL. We did not start another backend instance or claim live routing refresh across nodes. Unversioned writes remain potentially last-writer-wins; full multi-instance parity requires an explicit cache invalidation/reload mechanism with request-time consistency rules.

Management PATCH requests that omit `expectedVersion` now also use the atomic full-record SQL update, conditioned on the revision just read from PostgreSQL. A concurrent write between their read and write therefore returns HTTP 409 instead of silently overwriting the newer row; callers can re-read and retry. This preserves legacy no-version request shape while changing its conflict behavior. Explicitly versioned edits still check the supplied older revision. Local provider browser suite passed **7/7** after the change; backend check, health and diff check passed. Legacy PUT and backup upserts still have different overwrite semantics, and process-local inference caches on other nodes still need synchronization.

Provider management `PUT` is now **create-only**: `backend/src/database.rs#create_provider_if_absent` inserts all configured fields with `ON CONFLICT (slug) DO NOTHING`; `backend/src/providers.rs#put_provider` returns HTTP 409 if that slug already exists instead of replacing an existing provider's URL, key, enabled state or revision. The UI already uses PATCH for edits, and OAuth onboarding checks for collisions. Backup restore deliberately retains its separate upsert behavior. ### Pricing contract review

Read-only source comparison: Plexus's model editor offers Simple input/output/cached/cache-write rates in **USD per million tokens**, OpenRouter catalog slug/discount, bounded pricing ranges, and per-request flat fee (`.reference/plexus/packages/frontend/src/components/providers/model-editor/ModelPricing.tsx`). Adding editor pricing alone would mislead users and risk changing billing/usage reporting. The next implementable slice requires a typed pricing schema, request-time model ID mapping and token-category observations (including cache semantics), provenance (`cost_source`) and E2E against known provider responses. No price, cost, or production routing was changed during this review.

A later attempt to introduce only a `simple` input/output pricing schema was **withdrawn before deployment**: Trefoil's alias routing currently maps the display model ID to an upstream ID before dispatch, while its usage paths record the incoming alias and upstream-reported cost. Applying a local price after that remap without carrying the selected pricing entry through every success/failover/stream path could price the wrong model or a failed request. Both the temporary schema and its validation were removed; `cargo check` and `git diff --check` passed. Simple pricing remains intentionally unsupported until selected-target identity, complete token categories, upstream-cost precedence and cost provenance can be verified together with real requests. No UI-only rate fields were added.
